# Blender asset pipeline

Every 3D asset is **generated by a Python script** run inside Blender and exported as
glTF 2.0 binary (`.glb`) into `public/models/`. Scripts make assets reproducible and
reviewable in git, and let us change a dimension or colour and re-export in seconds.
Hand-modelled assets are still welcome: they follow the same naming contract below.

```
blender/scripts/*.py ──(blender -b -P … -- --export)──▶ public/models/**/*.glb ──▶ AssetLibrary (game)
                                                              │
                                              Phase 6: gltf-transform optimize (meshopt + KTX2)
```

**Requires Blender 4.2 LTS or newer.** `cyberpunk_car.py` is tested on 4.2.23 LTS and
5.0.1. Both export the same node tree, materials and vertex positions (vertex order can
differ between versions, which doesn't matter).

## The player car: `blender/scripts/cyberpunk_car.py`

![Player car preview](images/player_car_preview.jpg)

### Run it

| Where | How |
|---|---|
| Blender UI | *Scripting* workspace -> **Open** -> `cyberpunk_car.py` -> **Run Script**. Builds the car (collection `CAR_player_car`) and a wet-street preview stage (`PREVIEW_stage`). Switch the viewport to *Rendered* to see it. Re-running replaces both and leaves your other objects alone |
| Terminal (export) | `blender -b -P blender/scripts/cyberpunk_car.py -- --export public/models/cars/player_car.glb`, or `npm run assets:car` (needs `blender` on `PATH`) |
| Terminal (preview render) | `blender -b -P blender/scripts/cyberpunk_car.py -- --render docs/images/player_car_preview.jpg` (Cycles, about 3 min on 4 CPU cores at 128 samples) |

Options after `--`: `--export PATH`, `--preview` / `--no-preview`, `--render PATH`,
`--samples N`, `--paint HEX`, `--neon HEX`, `--accent HEX`. For example:
`-- --paint "#6a0f2a" --neon "#ffb000" --export public/models/cars/player_car_red.glb`.

### How it builds the car

1. **Body.** Eleven cross-section *stations* (the `STATIONS` table: half-width and height of
   floor, sill, shoulder, belt, roof edge and crown) are lofted into a closed faceted shell.
   Each segment has a zone tag that decides where the black glass goes.
2. **Creases and arches.** A bevel modifier chamfers creases over 28° so they catch
   highlights. An exact boolean cuts four wheel arches with inner liners. Both are then
   baked into the mesh.
3. **Aero.** Swept widebody over-fenders, a splitter with end plates, mirror pods, diffuser
   strakes, and a GT wing with an inverted aerofoil.
4. **Lights and neon.** Rays are cast onto the finished body (BVH tree), and thin profiles
   are swept along the hit points. Strips therefore hug the surface even after you edit the
   stations. This covers the headlight blade and "eye" slits, the twin tail bars, the door
   slash, the underglow, the splitter lip and the wing edge.
5. **Wheels.** Lathed tyre (with grooves), rim, brake disc, hub and hex nut, six curved
   dished spokes, and a neon lip ring. There is one mesh per axle, shared left/right.
6. **Game data.** A convex-hull collider, socket empties, and physics metadata on the root.

Everything is ~13k unique / ~21k drawn triangles, 10 materials, and 390 KB as a GLB
(102 KB after meshopt).

## Conventions

| | Blender | glTF / three.js |
|---|---|---|
| Units | 1 unit = 1 m | 1 unit = 1 m |
| Up | +Z | +Y |
| Vehicle forward | −Y (Blender's *Front* view shows the nose) | **+Z**, which is what `Object3D.getWorldDirection()` returns |
| Vehicle left | +X | +X |
| Vehicle origin | ground level, midway between the axles | same |

The exporter converts axes (`export_yup`), so nothing is rotated at runtime.

## Naming contract

The game finds everything by name, so any vehicle that follows this table works without
code changes.

| Node | Kind | Meaning |
|---|---|---|
| `<asset_id>` (e.g. `player_car`) | empty, root | Carries the metadata `extras` below |
| `BODY`, `BODY_*` | mesh | Visual body parts. Any number, any split |
| `WHEEL_FL` `WHEEL_FR` `WHEEL_RL` `WHEEL_RR` | empty | Wheel pivot at the hub centre, identity rotation. The game moves it for suspension and yaws it for steering |
| `WHEEL_XX_mesh` | mesh, child of pivot | What spins. Right-side wheels carry a 180° rotation (never negative scale) |
| `SOCKET_*` | empty | Attachment points: `headlight_L/R`, `taillight`, `underglow`, `exhaust_L/R`, `cam_target` |
| `COL_*` | mesh | Physics only. `extras.collider = "convex_hull"`. Hide it at runtime |

| Material prefix | Runtime behaviour |
|---|---|
| `CAR_*` | Static PBR: `CAR_Paint` (clearcoat, livery colour), `CAR_Glass`, `CAR_Trim`, `CAR_Underbody` |
| `WHEEL_*` | Tyre and rim |
| `NEON_Primary`, `NEON_Secondary` | Emissive; the game recolours or pulses them (livery, combo feedback) |
| `LIGHT_Head`, `LIGHT_Tail` | Emissive; the game drives intensity (headlights on/off, brake lights) |

Root `extras` (become `userData` in three.js):

| Key | Example | Used by |
|---|---|---|
| `asset_type` | `"vehicle"` | AssetLibrary routing |
| `asset_id` | `"player_car"` | Save data, garage |
| `pipeline_version` | `1` | Bump when this contract changes |
| `mass_kg` | `1250` | Rapier body mass |
| `wheelbase`, `track_front`, `track_rear` | `2.7`, `1.68`, `1.7` | Vehicle model |
| `wheel_radius`, `tire_width_front`, `tire_width_rear` | `0.34`, `0.26`, `0.31` | Suspension rays, visuals |

### Using it from the game (Phase 1 `VehicleVisual`)

```ts
const root = gltf.scene.getObjectByName("player_car")!;
const { wheel_radius, mass_kg } = root.userData;

// Wheels: steer and suspension on the pivot, spin on the mesh node.
const pivot = root.getObjectByName("WHEEL_FR")!;
const spinNode = root.getObjectByName("WHEEL_FR_mesh")!;
const rest = spinNode.quaternion.clone();              // keeps the right-side 180° flip
pivot.rotation.y = -steer * maxSteerAngle;             // +Y rotation turns toward +X (left)
pivot.position.y = restHeight + suspensionOffset;
spinNode.quaternion.copy(rest).premultiply(spin.setFromAxisAngle(X_AXIS, wheelAngle)); // + = rolling forward

// Lights and neon: materials are shared, so one assignment updates every mesh using them.
tailLightMaterial.emissiveIntensity = braking ? 20 : 7;
neonPrimary.emissive.set(livery.neon);

// Physics hull.
root.getObjectByName("COL_body")!.visible = false;
```

## Material rules

- **Principled BSDF only**, with plain values or image textures. That's all the glTF exporter
  understands. Procedural textures (noise and so on) don't export: bake them to images first.
  - Coat Weight / Roughness -> `KHR_materials_clearcoat` (three.js `MeshPhysicalMaterial`)
  - Emission Strength > 1 -> `KHR_materials_emissive_strength` (three.js `emissiveIntensity`)
- **Glass is opaque.** Near-black, roughness 0.02: it reflects the neon like glass but needs
  no transparency sorting and no interior.
- Colours in scripts are written as sRGB hex and converted to linear, which is what Blender
  stores.
- Reuse material names across assets (for example every traffic car uses `CAR_Glass`), so
  the game shares them.

## Export settings

`export_glb()` in the car script is the reference: GLB, selection = the asset's collection
only, apply modifiers, +Y up, **custom properties on** (`export_extras`), no cameras or
lights or animation. Preview-stage objects are never exported.

## Optimising (Phase 6)

Keep the node-preserving flags. The default `optimize` preset flattens, joins and prunes
the scene, which **deletes the `WHEEL_*` pivots, `SOCKET_*` empties and the root**:

```bash
npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt \
  --flatten false --join false --instance false --palette false --simplify false --prune false
```

Verified on the player car: 390 KB -> 102 KB, all 21 nodes, `extras` and materials intact,
0 validator errors. The loader then needs `gltfLoader.setMeshoptDecoder(MeshoptDecoder)`.
Add `--texture-compress ktx2` once assets carry textures (and `KTX2Loader` in the game).

## Adding a new asset: checklist

1. New script in `blender/scripts/`, modelled on `cyberpunk_car.py`: a spec dataclass,
   `build_*()` functions, `--export`, `--preview`, and cleanup on re-run.
2. Follow the conventions and naming contract above. Put physics numbers in root `extras`.
3. Stay inside the budget table; print the triangle count if unsure.
4. Export to `public/models/<category>/<asset_id>.glb` and commit the `.glb`, so the game
   builds without Blender.
5. Validate: drop the file on <https://github.khronos.org/glTF-Validator/>, expecting 0 errors.
6. When a second script needs the same helpers (`sweep`, `lathe`, `principled_material`,
   `export_glb`), move them to `blender/scripts/lib/` (planned for Phase 3).
7. Hand-edited `.blend` sources go in `blender/source/` under Git LFS.
